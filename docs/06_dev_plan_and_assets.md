# 06. 개발 계획 및 3D 에셋 교체

## 기술 스택 제안

| 항목 | 제안 | 이유 |
|------|------|------|
| 엔진 | 웹 3D (Three.js 또는 Babylon.js) | 설치 없이 브라우저에서 바로 실행, 아이 태블릿에서도 열림. 3D 파일(.glb) 교체가 쉬움 |
| 언어 | TypeScript | 데이터(JSON) 타입 체크 |
| 3D 모델 포맷 | glTF 2.0 (.glb) | 웹 표준. 블렌더/대부분의 3D 툴에서 내보내기 가능 |
| 드래프트 모델 | 코드로 만든 기본 도형(구, 큐브, 원기둥) | 파일 없이도 게임이 돌아가고, 나중에 .glb를 넣으면 자동 교체 |
| 데이터 | `data/*.json` | 몬스터/숫자블록/지역 정보를 코드와 분리해 아이와 같이 수정 가능 |
| 저장 | 브라우저 localStorage | 세이브 3칸 |

대안: Godot 4(무료, 아이와 함께 씬 편집 가능). 웹 빌드도 지원하지만 .glb 교체 파이프라인은 위와 동일.

## 3D 파일 교체 방법 (드래프트 → 진짜 캐릭터)

1. 모델 파일을 `.glb`로 준비한다. (.fbx/.obj 면 블렌더에서 glTF로 내보내기, 텍스처 포함)
2. `assets/models/` 폴더에 넣는다. 예: `assets/models/m03_bbogeul.glb` (GitHub 웹의 Add file → Upload files 로 올려도 된다)
3. `data/creatures.json` 에서 그 몬스터의 `"model"` 값을 파일 이름으로 바꾼다.
   - `"model": null` 이면 드래프트 도형이 나온다.
   - `"model": "m03_bbogeul.glb"` 이면 그 파일이 나온다.
   - 주인공은 `assets/models/player.glb` 를 넣으면 설정 없이 바로 바뀐다.
4. 게임을 새로고침하면 바로 바뀐다. (구현: `src/models.js` 가 모델을 뒤에서 받고, 도착하는 대로 시작 화면·게임 안의 드래프트 도형을 그 자리에서 모델로 바꾼다. 없는 파일은 드래프트 도형으로 남는다)

모델 규격:

| 항목 | 규격 |
|------|------|
| 크기 | 높이 약 1m (주인공 키 = 1m 기준). 코드에서 `scale` 값으로 보정 가능 |
| 원점 | 발바닥 중앙 (0, 0, 0) |
| 앞 방향 | +Z (게임의 드래프트 캐릭터·현재 모델들과 동일. 뒤를 보고 나오면 180° 돌려 내보내기) |
| 애니메이션(선택) | `idle`, `walk` 이름의 클립이 있으면 자동 재생(`happy`는 아직 미사용). 이름이 다르면 첫 클립을 계속 재생, 없으면 통통 튀는 기본 동작만 |
| 폴리곤 | 1만 이하 권장(태블릿용) |

숫자블록 친구도 같은 방식으로 `data/numberblocks.json`의 `"model"`을 바꾸면 교체된다.

## 저작권 관련 운영 원칙

- 저장소에는 포켓몬/넘버블럭스 공식 이미지·모델을 올리지 않는다. `assets/models/`의 `.glb`는 커밋되어 GitHub Pages로 공개 배포되므로, 직접 만들었거나 배포 가능한 모델만 올린다.
- 게임 안 이름은 전부 자체 이름을 쓴다(뽀글이, 원이 등). 공개 배포할 일이 생기면 그대로 써도 문제없도록.
